PsyDuck 解决什么问题

用 Claude Code（配合 superpowers 工作流）做开发时，有两样东西很容易失控：

  1. 代码包的 spec（SPEC.md）——改完代码后，描述这个包“做什么、暴露什么 API”的文档常常忘记更新，慢慢就和代码对不上了。
  2. 设计文档——brainstorm、plan 阶段产出的设计稿散落在 docs/ 下，代码改完没人归档，越积越多。

PsyDuck 用一个极简二进制 psy 加两个斜杠命令，把这两件事在变更结束时自动收尾：

  • 为本次改动触及的每个代码包刷新 SPEC.md（永远反映当前代码）
  • 把本次产出的设计文档归档进 .psy/<日期>/

关键定位：PsyDuck 只管生命周期（何时同步、归档到哪），不生成内容。 写 spec、写文档的具体内容交给 superpowers 等技能完成。

典型应用场景

场景一：日常开发中自动维护 spec（最常用）

仓库已经接入 PsyDuck。每次做新功能或改动，走标准 superpowers 流程：

brainstorming → writing-plans → executing-plans → /psy-sync自动
  • 前三步由 superpowers 技能驱动：探讨需求、产出计划、执行计划改代码。
  • 计划阶段的设计文档落在 docs/superpowers/specs/。
  • 当 executing-plans 结束，/psy-sync 自动触发，无需手动：
    • 给被改动的代码包刷新 SPEC.md
    • 把刚才那份设计文档移动归档到 .psy/2026-06-18/

自动触发靠的是 psy init 写进 CLAUDE.md 的那条规则——所以“初始化”和“日常自动收尾”是连起来的。

价值：你不必记得“改完代码去更新文档”，工作流替你兜底。

场景二：给一个已有代码库补 spec（Bootstrap）

接手一个老项目，没有任何 SPEC.md。用全量命令一次性生成基线：

/psy-sync-all

它会遍历整个仓库，为每个识别到的代码包生成 SPEC.md，并把 docs/superpowers/specs/ 下所有散落文档归档。首次运行 diff 很大，建议批量审查后再提交。

场景三：修复 spec 漂移（Drift Recovery）

某次改动没走 PsyDuck 流程（比如手动改了代码，或别人重构没同步），导致 spec 和代码对不上。再跑一次 /psy-sync-all 重新对齐即可。

/psy-sync vs /psy-sync-all：前者是变更集范围——只管刚做完的那次工作；后者是全仓库范围——用于 bootstrap 或修漂移。

安装与初始化

setup ~ %

psy init 做两件事：

  • 创建 .psy/ 目录（归档根目录）
  • 在项目 CLAUDE.md 末尾追加“读 SPEC.md、变更结束调 /psy-sync”的规则（已存在则跳过，幂等）

--install-plugins 把内置技能安装为 Claude Code 的全局斜杠命令（~/.claude/skills/<name>/SKILL.md），之后就能直接用 /psy-sync、/psy-sync-all。已存在的同名技能会被跳过，不会覆盖你的自定义。

--install-plugins 与初始化互相独立：即便仓库已经初始化过，也能单独再跑 psy init --install-plugins 只补装命令。

最小化安装（只建 .psy/、不装斜杠命令）：psy init。

日常使用速查

你想做的事 用什么
第一次接入 / 单独补装斜杠命令 psy init --install-plugins
查看版本 psy version
一次正常改动结束，收尾 spec + 归档 /psy-sync（通常自动触发）
给整个仓库生成 / 重新对齐 spec /psy-sync-all（手动，仅 bootstrap 或漂移时）

两个产物：你需要知道的

SPEC.md —— 每个代码包的“现状说明书”

  • 位置：代码包目录内（如 internal/cli/SPEC.md）。
  • 由技能自动维护，你通常不需要手写；需要时也可手动编辑，技能会保留已有内容。
  • 内容用中文，结构固定：概述 / 文件 / API / 依赖 / 设计重点。
  • 带 front-matter（psy_kind、psy_version、package），标准 markdown + YAML，grep 友好。

.psy/ —— 设计文档的归档处

  • 结构：.psy/<YYYY-MM-DD>/<文档名>.md。
  • 来源：docs/superpowers/specs/*.md 下的设计文档；归档时移动而非复制，原位置被清空，git 历史保留。
  • 同名冲突自动追加 -2、-3。

注意事项

  • 不联网、不调 LLM：psy 二进制只读写本地文件，内容生成全部交给 superpowers 等技能。
  • 变更集为空时不强行扫描：/psy-sync 发现没有改动会直接告诉你，不会擅自做全量扫描。
  • executing-plans 之后别跳过 /psy-sync：这是让“spec 与代码一致”的兜底步骤。
